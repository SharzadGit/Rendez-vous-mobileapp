# Reproducing the Bengaluru comparison

Use Python 3.12 and the repository root as the working directory. The checked-in extract is sufficient for offline routing. The regional source is 545,961,425 bytes. The bounded archive is about 3 MiB.

```sh
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# Windows PowerShell:
.venv\Scripts\Activate.ps1
python -m pip install -r research/requirements.lock
python -m unittest discover -s research/tests -v
python research/run.py all
```

The single entry point verifies the compressed snapshot, constructs all three networks, runs the prespecified three-mode pilot, checks independent routes and polygon intersections, then completes or resumes the balanced design, statistics, and figures. For separate phases use `pilot`, `run`, or `analyse`. A scenario checkpoint becomes complete via atomic replacement of its final JSON after matrix and route files have been written. Scenario IDs, fixed seeds and source/data/lock hashes isolate configurations in `research/work`. Run one writer per checkout. Wall-clock timings and process RSS will vary by host. Result files and numerical venue IDs can be inspected without installing Flutter.

## Files and reconstruction

- `configs/design.json` defines the WGS84 bounding box (west, south, east, north), routing halo, grid, precision, seeds and factors. `reports/analysis-protocol.md` describes estimands and statistical tests.
- `data/snapshot.json` gives the dated PBF URL, source and archived checksums, data timestamp and extraction scope. `scripts/snapshot.py` can rebuild the archive in a separate checkout with the compressed extract removed. It downloads the fixed PBF if necessary and verifies the published MD5. Check the source SHA-256 as well. Different zlib implementations can change compressed bytes. Compare the uncompressed JSON for semantic identity. Archive layout is `nodes[id]=[lon,lat]`, `features=[id,version,lon,lat,tags]`, `ways=[id,version,tags,node_refs]`. Way parts stop at the halo boundary.
- `data/graphs.json` counts active nodes, unique directed arcs and connected components. `data/venues.csv` gives public OSM POI identities, coordinates and the three road-node snaps.
- `results/manifest.csv` enumerates all planned scenarios. `missing.csv` identifies unexecuted scenarios. `failures.csv` includes failed primary and sensitivity decisions, whereas `scenarios.csv.gz` contains all decisions and timing components. A failed decision has no venue or invented travel time.
- `origins.csv.gz` and `participants.csv.gz` join through scenario, jitter flag, label and zero-based participant order. Baseline rows use jitter=false. `jitter_*` rows use jitter=true. Durations are seconds. `stages.csv.gz` holds shared Dijkstra searches, settled visits, post-surface process RSS samples and wall time. Verification timings attach to the first decision using a destination in each scenario/perturbation. Cache-hit rows reuse its result. Summing both shared and exclusive stages once avoids duplicate billing.
- `overall.csv`, `by_mode.csv`, `by_size.csv`, `by_pattern.csv`, and `by_cell.csv` report all attempts and conditional travel outcomes. `paired.csv` gives every method pair, units, confidence limits, percentage-denominator counts, sign-test p-values and Holm-adjusted p-values. `sensitivity.csv` and `rank_changes.csv` describe perturbations. `pareto.csv.gz` contains one representative per nondominated mean–maximum coordinate pair.
- `venue_matrices.zip` is regenerated locally by the analysis step. This 35 MiB archive is excluded from version control. It contains one NumPy NPZ per scenario with float64 seconds (origin rows, venue columns), OSM IDs for both axes and infinity for each unreachable pair. Run `python research/scripts/audit.py` to verify all primary selections and classify failures independently of the selection code.
- `results/pilot.json` records independent heap and predecessor checks. Pilot route coordinates (UTM metres), contour masks, and all private computation checkpoints are regenerated in the hash-named work directory. Each published map and chart is generated by `scripts/figures.py`.
- Editable paper and reviewer correspondence are in `reports/`. Build instructions accompany the manuscript.

## Routing model and computational accounting

Synthetic target coordinates are snapped to distinct study-area OSM vertices present in all three mode graphs, without restricting origins to their largest connected components. A replica uses the same vertices in all three modes. Venues are named node POIs tagged cafe, restaurant, library or community_centre, with unrestricted access under the stated tag filter, and a nearest active vertex within 75 m for every profile. Eligibility uses mapped POI positions. Route time ends at the mode-specific road node and excludes off-road entrance travel. No personal movement traces, provider key or live service measurements enter the experiment.

The graph uses unsimplified OSM way segments, projected in EPSG:32643. Shared OSM node identity determines junctions. Parallel arcs keep their fastest cost. Walking uses 4.8 km/h (3 on steps), bicycle 15 (8 on paths, tracks, footways and steps), and driving 12–65 by class subject to parseable posted numeric limits. `network.py` specifies allowed classes, explicit access precedence, barriers, directional overrides, roundabouts and bicycle contraflow. Conditional-tagged ways for the applicable access keys are conservatively excluded. The model omits turn-restriction relations, turn/signal delays, real-time traffic, schedules, building entrances, elevation and some conditional or lane-specific rules. Boundary truncation can disconnect valid real-world paths. A failed scenario is evidence about the modeled graph and finite venues.

Full forward Dijkstra searches give every venue score and network vertex arrival time. Because native SciPy exhausts the reachable component with positive weights and no cutoff, counting finite labels gives settled vertices including each source. It does not measure heap operations. Traversal counts include repeat visits across different origin searches. The scenario wall-time components distinguish common routing/surface preparation, exclusive ranking (including timed geometry/venue filtering in isochrone), and reverse-search verification. Allocation samples are process working set, not peak algorithm memory. There are zero provider requests and zero provider wait seconds. In the uniform-speed sensitivity all edge times scale exactly by 1.25.

## Flutter and hosted services

Use Flutter 3.38.9 / Dart 3.10.8; restore the checked-in pubspec.lock and run `flutter test --no-pub` and `flutter test --no-pub --platform chrome`. Windows may require Developer Mode for native plugin symlinks. On Windows with this SDK, if the web test server returns 404 for its own CanvasKit assets, copy the SDK's entire `bin/cache/flutter_web_sdk/canvaskit` directory to `packages/flutter_tools/canvaskit` inside the local SDK. This uses the tool's static asset handler. Set CHROME_EXECUTABLE to an actual Chrome/Chromium headless binary when necessary.

The optional hosted service composes the existing ORS matrix, group contour optimizer, polygon intersection, category/venue filter and directions verifier. Its matrix-qualified threshold predicate preserves the geometric overlap audit. The three stage budgets are explicit. Use an authenticated and rate-limited server-side proxy and configure only its public URL with ORS_BASE_URL. Account owners must revoke the historical exposed key. The Flutter UI retains its original interactive heuristics. The Python experiment implements the documented finite-venue comparison on the fixed graph.
